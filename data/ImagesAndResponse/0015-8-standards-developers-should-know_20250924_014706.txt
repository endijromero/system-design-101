### Análisis Exhaustivo de 8 Estándares Esenciales para Desarrolladores

#### 1. Descripción General

La infografía presenta ocho estándares tecnológicos fundamentales que todo desarrollador de software, especialmente en el ámbito web, debería conocer. Estos estándares no son lenguajes o frameworks específicos, sino las reglas, protocolos y especificaciones que sustentan la comunicación, la estructura de datos, la seguridad y la interoperabilidad en la tecnología moderna. El propósito de la imagen es ofrecer una visión general de alto nivel de estos pilares, explicando brevemente su función y por qué son cruciales. Abarca desde las capas más bajas de la red (TCP/IP) hasta las especificaciones de APIs (OpenAPI), mostrando el ecosistema completo en el que operan los desarrolladores.

### 1. TCP/IP (Transmission Control Protocol/Internet Protocol)

Descripción del Panel: El panel ilustra el concepto de capas de red. Muestra cómo un mensaje (sobre) o un paquete de datos (caja) viaja desde un origen a un destino, pasando por diferentes medios de transporte (trenes, aviones), análogo a cómo los datos se encapsulan y viajan a través de las capas del modelo TCP/IP. A la derecha, se muestra la pila de protocolos TCP/IP, desde la capa física (Ethernet) hasta la de aplicación (HTTP), destacando su rol como "la fundación de internet".

Conceptos Clave:
    TCP (Transmission Control Protocol): Es un protocolo orientado a la conexión que garantiza que todos los paquetes de datos lleguen al destino en el orden correcto y sin errores. Realiza un "apretón de manos" de tres vías (three-way handshake) para establecer una conexión fiable.
    IP (Internet Protocol): Es responsable de direccionar los paquetes de datos (datagramas) para que puedan viajar a través de las redes y llegar a su destino correcto. Se encarga del enrutamiento. No garantiza la entrega.
    Suite de Protocolos: TCP/IP no es un solo protocolo, sino una suite (un conjunto) que incluye muchos otros, como UDP (alternativa a TCP, más rápida pero no fiable), HTTP, FTP, SMTP, DNS, etc., organizados en capas.
    Capas (Layering): El modelo divide la compleja tarea de la comunicación en red en capas de abstracción. Cada capa se ocupa de una tarea específica y solo se comunica con las capas adyacentes. Las capas comunes son: Aplicación, Transporte, Internet (o Red) y Enlace de Datos/Física.

Explicación Pedagógica:
    Imagina que quieres enviar un libro largo a un amigo en otro país.
    1.  Capa de Aplicación (Tú decides qué enviar): Decides enviar el libro "Don Quijote". Esto es como el protocolo HTTP que decide qué página web solicitar.
    2.  Capa de Transporte (TCP lo empaqueta): El libro es demasiado grande para un solo sobre. Lo divides en capítulos, numeras cada página y las pones en sobres separados. TCP hace esto: divide los datos en segmentos, los numera y se asegura de que todos lleguen en orden. Si un sobre se pierde, pide que se reenvíe.
    3.  Capa de Internet (IP pone la dirección): En cada sobre, escribes la dirección completa de tu amigo y tu dirección de remitente. IP hace esto: añade las direcciones IP de origen y destino a cada paquete.
    4.  Capa de Enlace/Física (El servicio postal lo transporta): Llevas los sobres a la oficina de correos. Ellos los transportarán por camión, avión, etc., hasta la oficina de correos local de tu amigo. Esta capa se encarga del transporte físico de los bits a través de cables, fibra óptica o Wi-Fi.
    El amigo recibe los sobres, los ordena según la numeración de las páginas y vuelve a montar el libro. TCP/IP funciona de manera muy similar para los datos en internet.

Contexto y Aplicaciones: TCP/IP es, literalmente, el lenguaje de internet. Cada dispositivo conectado a internet (tu teléfono, tu portátil, los servidores de Google) utiliza esta suite de protocolos para comunicarse. Sin TCP/IP, no existiría la World Wide Web, el correo electrónico, ni prácticamente ningún servicio en línea que conocemos hoy. Fue desarrollado en la década de 1970 por DARPA (la Agencia de Proyectos de Investigación Avanzados de Defensa de EE. UU.) y es la base de las redes públicas y privadas en todo el mundo.

Relaciones: TCP/IP es el fundamento sobre el que se construyen muchos otros estándares de esta lista. HTTP (2) es un protocolo de la capa de aplicación que se ejecuta sobre TCP/IP. Las comunicaciones para OAuth (4), las solicitudes a bases de datos a través de una red (SQL (3)) o las interacciones con una API definida por OpenAPI (8), todas dependen de TCP/IP para transportar los datos de manera fiable a través de la red.

### 2. HTTP (Hypertext Transfer Protocol)

Descripción del Panel: Se muestra un navegador web (cliente) enviando una solicitud a un servidor. La solicitud es un texto plano con comandos como `GET / HTTP/1.1` y cabeceras (`Host`, `User-Agent`, etc.). El servidor procesa esta solicitud. Se destaca que es el protocolo de red web más famoso y que es un protocolo de texto, fácil de usar.

Conceptos Clave:
    Protocolo Cliente-Servidor: La comunicación se basa en un cliente (como un navegador) que realiza solicitudes y un servidor que las responde.
    Sin Estado (Stateless): Cada solicitud HTTP es independiente. El servidor no guarda información sobre solicitudes anteriores del mismo cliente. Para mantener el estado (como una sesión de inicio de sesión), se utilizan técnicas como las cookies.
    Métodos (Verbos): Definen la acción que se desea realizar. Los más comunes son `GET` (solicitar un recurso), `POST` (enviar datos para crear un recurso), `PUT` (actualizar un recurso) y `DELETE` (eliminar un recurso).
    Cabeceras (Headers): Metadatos que acompañan a la solicitud y la respuesta, proporcionando información contextual (tipo de contenido, codificación, autenticación, etc.).
    Códigos de Estado: Números de tres dígitos en la respuesta que indican el resultado de la solicitud (p. ej., `200 OK`, `404 Not Found`, `500 Internal Server Error`).

Explicación Pedagógica:
    Piensa en HTTP como el idioma formal que se usa para pedir comida en un restaurante muy organizado.
    *   Tú (el cliente/navegador) tienes un menú (la web).
    *   Llamas al camarero y haces un pedido claro: "QUIERO (`GET`) el plato principal (`/index.html`)". También le das detalles adicionales en una servilleta (las cabeceras), como: "Soy alérgico al gluten" (`Accept: text/html`) y "Estoy en la mesa 5" (`Host: www.example.com`).
    *   El camarero (el servidor) lleva tu pedido a la cocina.
    *   Cuando la comida está lista, te la trae con una respuesta. La respuesta puede ser: "Aquí tienes tu plato" (código 200 OK con la página web) o "Lo siento, se nos ha acabado ese plato" (código 404 Not Found).
    *   Es "sin estado" porque el camarero no se acuerda de tu pedido anterior. Cada vez que pides algo, tienes que hacerlo desde cero.

Contexto y Aplicaciones: HTTP es la columna vertebral de la World Wide Web. Cada vez que visitas un sitio web, ves una imagen o ves un video en tu navegador, se está utilizando HTTP (o su versión segura, HTTPS). También es la base de las APIs RESTful, que son la forma más común en que las aplicaciones se comunican entre sí en internet.

Relaciones: HTTP se ejecuta sobre TCP/IP (1). Las páginas web que transfiere están escritas en HTML/CSS (5) y ECMAScript/JavaScript (6). Los flujos de autenticación de OAuth (4) se realizan mediante redirecciones y llamadas HTTP. Las APIs de OpenAPI (8) definen endpoints HTTP.

### 3. SQL (Structured Query Language)

Descripción del Panel: El panel muestra que los comandos SQL se dividen en varias categorías: DDL, DML, TCL, DQL y DCL. Para cada categoría, se enumeran comandos de ejemplo. Esto ilustra que SQL es más que solo consultar datos; es un lenguaje completo para gestionar bases de datos relacionales.

Conceptos Clave:
    DDL (Data Definition Language): Lenguaje de Definición de Datos. Se usa para definir y gestionar la estructura de la base de datos. Comandos: `CREATE` (crear tablas), `ALTER` (modificar tablas), `DROP` (eliminar tablas).
    DML (Data Manipulation Language): Lenguaje de Manipulación de Datos. Se usa para interactuar con los datos dentro de las tablas. Comandos: `INSERT` (añadir datos), `UPDATE` (modificar datos), `DELETE` (eliminar datos).
    DQL (Data Query Language): Lenguaje de Consulta de Datos. Se usa para recuperar datos. El comando principal es `SELECT`. A menudo se considera parte del DML.
    DCL (Data Control Language): Lenguaje de Control de Datos. Se usa para gestionar permisos y acceso a la base de datos. Comandos: `GRANT` (conceder permisos), `REVOKE` (revocar permisos).
    TCL (Transaction Control Language): Lenguaje de Control de Transacciones. Gestiona las transacciones para asegurar la integridad de los datos. Comandos: `COMMIT` (guardar cambios), `ROLLBACK` (deshacer cambios), `SAVEPOINT`.

Explicación Pedagógica:
    Imagina que una base de datos es un gran archivador de oficina.
    DDL: Es como diseñar el archivador. Decides cuántos cajones tendrá (`CREATE TABLE`), qué etiquetas pondrás en cada cajón (`CREATE COLUMNS`) y si necesitas añadir o quitar un cajón más tarde (`ALTER TABLE`).
    DML: Es el trabajo diario con los archivos. Metes un nuevo documento en un cajón (`INSERT`), corriges un error en un documento existente (`UPDATE`) o tiras un documento a la basura (`DELETE`).
    DQL: Es cuando necesitas encontrar información. Abres un cajón y buscas todos los documentos que cumplan ciertos criterios (`SELECT ... WHERE ...`).
    DCL: Es el gerente de la oficina decidiendo quién puede acceder a qué archivador. A un empleado le das la llave de un cajón (`GRANT`), pero si cambia de departamento, se la quitas (`REVOKE`).
    TCL: Es para tareas delicadas. Si estás moviendo varios documentos importantes entre cajones, o lo haces todo con éxito (`COMMIT`), o si algo sale mal a mitad de camino, devuelves todos los documentos a su sitio original (`ROLLBACK`).

Contexto y Aplicaciones: SQL es el lenguaje estándar para interactuar con bases de datos relacionales (como MySQL, PostgreSQL, SQL Server, Oracle). Prácticamente cualquier aplicación que necesite almacenar datos de forma estructurada (usuarios, productos, pedidos, etc.) utiliza una base de datos y, por tanto, SQL. A pesar de la aparición de bases de datos NoSQL, SQL sigue siendo una habilidad fundamental y extremadamente demandada.

Relaciones: Una aplicación web (construida con HTML/CSS (5) y ECMAScript (6)) se comunica a través de HTTP (2) con un servidor. Este servidor a menudo ejecuta lógica de negocio que interactúa con una base de datos utilizando SQL (3) para almacenar y recuperar datos. Las credenciales de usuario para OAuth (4) o los datos de una API de OpenAPI (8) se guardan en estas bases de datos.

### 4. OAuth

Descripción del Panel: Se visualiza el flujo de autorización delegada con tres actores principales: "Resources Owner" (Propietario de Recursos), "Client" (Cliente) y "Auth Center" (Centro de Autorización). El propietario concede permiso al centro de autorización, que a su vez autoriza al cliente para que este pueda acceder a los recursos del propietario.

Conceptos Clave:
    Autorización Delegada: Es el concepto central. Un usuario (Resource Owner) permite que una aplicación de terceros (Client) acceda a sus datos alojados en otro servicio (Resource Server), sin compartir sus credenciales (usuario y contraseña).
    Roles:
        Resource Owner: El usuario final que posee los datos.
        Client: La aplicación que quiere acceder a los datos.
        Authorization Server (Auth Center): El servidor que autentica al usuario y emite los tokens de acceso.
        Resource Server: El servidor que aloja los datos y acepta los tokens de acceso.
    Token de Acceso (Access Token): Una "llave" temporal y con permisos limitados que el cliente usa para hacer solicitudes a la API del servidor de recursos en nombre del usuario.

Explicación Pedagógica:
    El mejor análogo es el valet parking de un hotel.
    *   Tú (el Resource Owner) eres el dueño del coche (el Recurso).
    *   El servicio de valet (el Client) quiere aparcar tu coche.
    *   No le das la llave maestra de tu casa ni tu DNI (tus credenciales). Le das solo la llave del coche (el Access Token).
    *   Esta llave solo puede hacer una cosa: arrancar y mover el coche (tiene un alcance limitado). Además, se la devolverás al final del día (tiene una vida útil limitada).
    *   El hotel (el Authorization Server) es quien gestiona la entrega de llaves y se asegura de que solo los valets autorizados las reciban.

Contexto y Aplicaciones: OAuth (especialmente OAuth 2.0) es el estándar de facto para la autorización en la web. El ejemplo más común es el inicio de sesión con "Log in with Google/Facebook/GitHub". Cuando una aplicación te pide permiso para acceder a tus contactos, calendario o fotos de Google, está utilizando el flujo de OAuth.

Relaciones: El flujo de OAuth se implementa completamente sobre HTTP (2) y TCP/IP (1). El "Client" suele ser una aplicación web (construida con HTML/CSS (5) y ECMAScript (6)). Los detalles de la API que se protege con OAuth a menudo se especifican en un documento OpenAPI (8). La información sobre los clientes registrados y los permisos de usuario se almacena en una base de datos gestionada con SQL (3).

### 5. HTML/CSS

Descripción del Panel: El panel muestra un icono de código que representa un archivo HTML/CSS. Este archivo se convierte, siguiendo la "HTML/CSS Specification", en una página web renderizada en navegadores como Chrome y Safari. Los beneficios clave son reducir el código de compatibilidad y crear una experiencia de usuario consistente.

Conceptos Clave:
    HTML (HyperText Markup Language): Es el lenguaje de marcado estándar para crear la estructura y el contenido de las páginas web. Utiliza etiquetas (como `<h1>`, `<p>`, `<img>`) para definir elementos como títulos, párrafos e imágenes.
    CSS (Cascading Style Sheets): Es el lenguaje utilizado para describir la presentación y el estilo de un documento escrito en HTML. Controla colores, fuentes, espaciados, diseños (layouts) y la adaptabilidad a diferentes dispositivos (responsive design).
    Separación de incumbencias (Separation of Concerns): El estándar promueve que HTML se encargue de la estructura (el "qué") y CSS se encargue del estilo (el "cómo se ve"), lo que hace que el código sea más limpio, mantenible y accesible.
    Especificación (W3C/WHATWG): Organismos como el World Wide Web Consortium (W3C) y el Web Hypertext Application Technology Working Group (WHATWG) crean y mantienen las especificaciones oficiales de HTML y CSS. Los navegadores se esfuerzan por implementar estas especificaciones para que una misma página web se vea y funcione de manera similar en todas partes.

Explicación Pedagógica:
    Construir una página web es como construir una casa.
    HTML es el esqueleto y la estructura: Son los cimientos, las paredes, el techo, las puertas y las ventanas. Define dónde está la cocina, dónde está el baño y cuántas habitaciones hay. Es la estructura fundamental.
    CSS es la decoración y el diseño de interiores: Es el color de la pintura en las paredes, el tipo de suelo, los muebles, las cortinas y la iluminación. No cambia la estructura de la casa, pero cambia completamente cómo se ve y se siente.

Contexto y Aplicaciones: HTML y CSS son las tecnologías básicas de la World Wide Web. Cualquier sitio web o aplicación web que veas en un navegador está construido con ellas. Son el primer paso para cualquier persona que quiera aprender desarrollo web front-end.

Relaciones: Las páginas HTML/CSS son el "producto final" que se entrega al usuario a través de HTTP (2). La interactividad de estas páginas se añade con ECMAScript (6). A menudo, el contenido de estas páginas se genera dinámicamente en un servidor que extrae datos de una base de datos SQL (3).

### 6. ECMAScript

Descripción del Panel: El panel muestra un diagrama de círculos concéntricos: ES5 en el centro, rodeado por ES6, y este a su vez por TypeScript. Esto ilustra que las versiones más nuevas de ECMAScript (como ES6) son superconjuntos de las antiguas, y que lenguajes como TypeScript son superconjuntos de ECMAScript. Se menciona su uso en navegadores y en el lado del servidor (Node.js).

Conceptos Clave:
    ECMAScript: Es la especificación (el estándar) de un lenguaje de scripting. Define las reglas, la sintaxis y las características que debe tener el lenguaje.
    JavaScript: Es la implementación más popular y conocida de la especificación ECMAScript. Los navegadores web (Chrome, Firefox, Safari) tienen "motores de JavaScript" que interpretan y ejecutan este código.
    Versiones (ES5, ES6/ES2015, etc.): La especificación ECMAScript evoluciona. ES5 (2009) fue la base de la web moderna durante años. ES6 (ECMAScript 2015) fue una actualización masiva que introdujo características modernas como clases, módulos y funciones de flecha. Las nuevas versiones salen anualmente.
    TypeScript: Es un superconjunto (superset) de JavaScript. Esto significa que todo el código JavaScript es código TypeScript válido, pero TypeScript añade características adicionales, principalmente el tipado estático, para crear aplicaciones más robustas y a gran escala.

Explicación Pedagógica:
    Piensa en ECMAScript como las "reglas del idioma español" establecidas por la Real Academia Española.
    ECMAScript es el libro de gramática y el diccionario oficial. Define cómo deben formarse las frases, qué palabras existen y qué significan.
    JavaScript es cómo la gente realmente habla español en el día a día. Aunque intentan seguir las reglas, cada región (navegador) puede tener su propio "acento" o pequeñas variaciones (implementación del motor de JS).
    ES6 fue una gran revisión del libro de reglas, añadiendo muchas palabras y construcciones gramaticales nuevas y útiles que hicieron el idioma más expresivo.
    TypeScript es como un español "técnico" o "formal" utilizado por los abogados. Sigue todas las reglas del español estándar, pero añade capas adicionales de precisión (tipos de datos) para evitar malentendidos en documentos importantes (aplicaciones grandes).

Contexto y Aplicaciones: ECMAScript (a través de JavaScript) es el único lenguaje de scripting que se ejecuta de forma nativa en los navegadores web, lo que lo hace indispensable para el desarrollo front-end. Con la llegada de Node.js, también se ha convertido en una opción muy popular para el desarrollo back-end, permitiendo a los desarrolladores usar el mismo lenguaje en toda la pila tecnológica (full-stack).

Relaciones: El código ECMAScript se ejecuta en páginas HTML (5) para añadir interactividad. Realiza llamadas de red asíncronas usando HTTP (2) (a través de la API Fetch o XMLHttpRequest) para comunicarse con APIs definidas por OpenAPI (8), a menudo autenticadas con OAuth (4).

### 7. ISO Data Format (ISO 8601)

Descripción del Panel: Se muestra el formato de fecha y hora `YYYY-MM-DDTHH:mm:ss.SSSZ`, descomponiéndolo en sus componentes: año, mes, día, hora, minuto, segundo, fracción de segundo y zona horaria. Se enfatiza que resuelve problemas de zonas horarias y facilita el análisis (parsing) e integración de datos.

Conceptos Clave:
    ISO 8601: Es un estándar internacional para la representación de fechas y horas. Su objetivo es evitar la ambigüedad y la confusión causadas por los diferentes formatos nacionales (p. ej., `MM/DD/YYYY` vs. `DD/MM/YYYY`).
    Formato: El formato más común es `YYYY-MM-DDTHH:mm:ss.sssZ`.
        *   `YYYY-MM-DD`: Fecha (año-mes-día).
        *   `T`: Un literal que separa la fecha de la hora.
        *   `HH:mm:ss.sss`: Hora (horas-minutos-segundos.milisegundos).
        *   `Z`: El designador de zona horaria. `Z` significa UTC (Tiempo Universal Coordinado, también conocido como Zulu time). También puede ser un offset como `+02:00` o `-05:00`.
    Ventajas:
        Inequívoco: Un `timestamp` en formato ISO 8601 tiene un solo significado posible.
        Ordenable: Al comenzar por la unidad de tiempo más grande (año) y terminar por la más pequeña, las fechas en este formato se pueden ordenar alfabéticamente y quedarán cronológicamente correctas.
        Legible por humanos y máquinas: Es relativamente fácil de leer para una persona y muy fácil de analizar para un programa.

Explicación Pedagógica:
    Imagina que estás organizando una conferencia telefónica internacional con gente de Estados Unidos, España y Japón. Si dices "nos vemos el 02/03/24 a las 9:00", la confusión es inmediata.
    *   Para el estadounidense, es el 3 de Febrero. Para el español, es el 2 de Marzo.
    *   ¿9:00 de la mañana de quién? ¿Tokio, Madrid o Nueva York?
    El formato ISO 8601 es como usar un sistema de coordenadas global y un reloj universal. Si dices "la reunión es el `2024-03-02T14:00:00Z`", todo el mundo sabe exactamente a qué instante de tiempo te refieres, sin importar dónde se encuentren. Solo tienen que convertir esa hora UTC a su hora local. Es el estándar que pone orden en el caos del tiempo.

Contexto y Aplicaciones: Este formato es omnipresente en la programación, especialmente en sistemas distribuidos, APIs y bases de datos. Se utiliza para registrar eventos (logs), marcar la creación o modificación de registros (`created_at`, `updated_at`), definir la expiración de tokens o sesiones, y en cualquier lugar donde la precisión temporal sea crítica.

Relaciones: Las APIs definidas con OpenAPI (8) suelen usar el formato ISO 8601 para todos los campos de fecha y hora. Los datos intercambiados vía HTTP (2), como en respuestas JSON, utilizan este formato. Las bases de datos SQL (3) almacenan `timestamps` que a menudo se representan o convierten a este formato para la comunicación entre servicios. Los tokens de OAuth (4) tienen una fecha de expiración que se expresa en un formato estándar, a menudo derivado de este.

### 8. OpenAPI

Descripción del Panel: El panel muestra un fragmento de código (probablemente en formato YAML o JSON, que define una API) que, a través de una herramienta (engranaje), genera automáticamente dos cosas: documentación de la API (icono de función) y código cliente (icono de API/circuito).

Conceptos Clave:
    Especificación OpenAPI (anteriormente Swagger): Es un estándar para describir APIs RESTful de una manera que sea legible tanto para humanos como para máquinas. La descripción se escribe en un archivo YAML o JSON.
    Contrato de API: El archivo OpenAPI actúa como un "contrato" formal entre el proveedor de la API y sus consumidores. Define qué endpoints están disponibles, qué operaciones (`GET`, `POST`) acepta cada uno, qué parámetros requieren y qué estructura tienen las respuestas.
    Ecosistema de Herramientas: La gran ventaja de OpenAPI es el ecosistema de herramientas que lo rodean. A partir de un único archivo de especificación, se puede:
        Generar Documentación Interactiva: Páginas web donde los desarrolladores pueden leer sobre la API e incluso probarla directamente desde el navegador.
        Generar SDKs/Código Cliente: Crear automáticamente el código necesario para consumir la API en diferentes lenguajes de programación (Python, Java, JavaScript, etc.).
        Generar Mocks de Servidor: Crear servidores de prueba que simulan el comportamiento de la API antes de que esté construida.
        Realizar Pruebas de Contrato: Validar que la implementación real de la API se ajusta a lo que dice la especificación.

Explicación Pedagógica:
    Piensa en la especificación OpenAPI como el plano detallado de un kit de muebles de IKEA.
    *   El plano (archivo OpenAPI) describe cada pieza, cada tornillo, y te da instrucciones paso a paso sobre cómo montar el mueble (la API).
    Documentación: El manual de instrucciones con dibujos claros que viene en la caja. Cualquiera puede leerlo y entender cómo funciona el mueble.
    Generación de Código Cliente: Es como si IKEA te diera una herramienta eléctrica a medida que solo sirve para montar ESE mueble específico. No tienes que buscar tus propias herramientas; ya tienes el código pre-hecho para interactuar con la API.
    Contrato: Si al final el mueble no se parece al de la foto del catálogo, sabes que algo está mal, ya sea en el plano o en las piezas. El plano sirve como la fuente única de verdad.

Contexto y Aplicaciones: OpenAPI es el estándar líder en la industria para el diseño y la documentación de APIs RESTful. Facilita enormemente la colaboración entre equipos de front-end y back-end, ya que ambos pueden trabajar basándose en el "contrato" de la API. Mejora la experiencia del desarrollador (DX) al proporcionar herramientas que automatizan tareas tediosas.

Relaciones: Una especificación OpenAPI describe una API que opera sobre HTTP (2). Los endpoints definidos pueden estar protegidos por OAuth (4). La API descrita probablemente interactúa con una base de datos SQL (3) en el back-end. Los datos intercambiados, como los `timestamps`, deben seguir el formato ISO 8601 (7). El código cliente generado podría ser en ECMAScript (6) para ser usado en una aplicación web construida con HTML/CSS (5).

### Conclusión: La Interconexión de los Estándares

Esta infografía no presenta ocho conceptos aislados, sino un ecosistema interconectado que define el desarrollo de software moderno. Un desarrollador crea una aplicación web (HTML/CSS, ECMAScript) que se comunica a través de la red (HTTP sobre TCP/IP) con una API documentada y diseñada con OpenAPI. Esta API, para ser segura, utiliza OAuth para la autorización y, en su lógica interna, consulta una base de datos SQL para gestionar datos. Para garantizar que no haya ambigüedades, todos los intercambios de fechas y horas se realizan en formato ISO 8601. Comprender no solo cada estándar por separado, sino cómo encajan y dependen unos de otros, es lo que distingue a un desarrollador competente de un experto.
